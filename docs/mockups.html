◆lazybw

A terminal UI for your Bitwarden vault, written in Rust with ratatui. It drives the official bw CLI, uses Tokyo Night by default and behaves like Vim.

personal vault · Linux requires bw ≥ 2025.9.0 ratatui 0.30 · crossterm 0.29 specs in docs/

Themes

Tokyo Night first, any theme after

No screen uses colours directly. Screens use named tokens, and each theme only fills them in. Click a theme to apply it to the mockups above.

  • One more theme, terminal, uses your terminal's 16 ANSI colours. It works with pywal, matugen or whatever theme kitty or foot already has.
  • Transparent background with transparent = true: lazybw stops painting the background and your terminal's shows through.
  • Your own themes in ~/.config/lazybw/themes/*.toml, with extends to change only what you want. They reload when you save, so you can tune colours with lazybw open.
  • Icons: nerdfont (default), unicode or ascii. With a Nerd Font, well-known sites get their logo (GitHub, Google, Reddit…).
  • Animations are subtle and on by default; animations = false turns them off.
# ~/.config/lazybw/config.toml
[ui]
theme        = "tokyonight-night"
transparent  = false
icons        = "nerdfont"
animations   = true

[keys]
leader = "<Space>"

[keys.list]
"<Del>" = "item.trash"     # add a key
"yl"    = "item.copy uri"  # action with an argument
"*"     = "noop"           # remove a default

# ~/.config/lazybw/themes/my-night.toml
extends = "tokyonight-night"
[palette]
accent = "#bb9af7"
Principles

The rules that settle the details

Keyboard first, Vim always

Everything works without the mouse, with counts, operators and modes. The mouse works for clicks and scrolling but is never required.

Secrets stay hidden

Revealing is explicit (za) and hides again after 20 seconds, when you move to another item or when the terminal loses focus. Copying never reveals.

One colour, one meaning

Each item type has its own colour in every theme. Red is only for danger and orange only for warnings.

Hints where the cursor is

Keys show up like inlay hints, only on the active row. The screen stays clean and the keys teach themselves.

The interface never freezes

Every call to bw runs in the background, with a spinner in the statusline and a message when it finishes. You can keep browsing while it syncs.

Fits any terminal

Three panes from 140 columns. Below 100 it shows one pane at a time (l goes in, h comes back) and works at 80×24 over SSH.

Architecture

The official bw does the cryptography, lazybw does the rest

lazybw never touches Bitwarden's cryptography. It starts bw serve as a child process and talks to it over a private socket.

lazybwRust · ratatui · tokio
HTTP/1.1 over a socketpair
fd 3, no TCP port
bw serveofficial CLI, child process
HTTPS · end-to-end
encrypted
Bitwarden server.com · .eu · self-hosted
As subprocesses, for what serve does not offer:bw statusbw loginbw logoutbw exportbw importbw report
  • Private socket. Plain bw serve listens on localhost:8087, where any process on the machine can read the unlocked vault. Since 2025.9.0, bw accepts --hostname fd+connected://3: only lazybw holds the other end, and the server stops when lazybw closes it.
  • Login outside serve. serve needs an existing login. The first time, lazybw suspends itself and runs bw login in the terminal, which handles two-step login, new device codes and SSO. Daily unlocking happens inside lazybw.
  • No secrets in arguments. Command lines are visible in ps. Import uses --passwordenv; the password-protected export answers bw's prompt through a PTY.
  • Edits never lose data. Every edit starts from the complete item and sends it back complete, including fields lazybw does not know about yet.
  • Memory. Secrets live in types that are wiped when dropped (secrecy, zeroize), core dumps are off, and logs never contain values.
  • Clipboard. Cleared after 30 seconds, but only if it still holds what lazybw copied. Copies carry the hint that tells clipboard managers like KDE's and cliphist to skip them.
  • $EDITOR. Temporary file in $XDG_RUNTIME_DIR (in RAM, mode 0600), Neovim opened without swap, undo or shada, deleted afterwards, as pass edit does.
  • TOTP without Premium. bw refuses bw get totp without Premium, so lazybw computes codes locally from the stored key (RFC 6238). A setting turns this off.
Decisions

What we settled

  1. Name: lazybw.

    Crate, binary and ~/.config/lazybw.

  2. English everywhere.

    Interface, code, comments, documentation and commit messages.

  3. Linux only.

    X11 and Wayland, local or over SSH.

  4. Personal vault, no Premium.

    No organizations, Send, attachments or archive. TOTP codes computed locally.

  5. First login with the TUI suspended.

    The real bw login handles every two-step method and SSO.

  6. Nerd Font icons by default.

    Unicode and ASCII fallbacks.

  7. Vim keys as proposed, all customizable.

    Space leader, m move, * favorite, x mark, u undo. Config file, keybinding editor and :map.

  8. Subtle animations, on by default.

    One setting turns them off.
